Elasticsearch Platform

可观测性、安全和搜索等三大解决方案 — 由 Elasticsearch 平台提供支持。

Elasticsearch

Elastic Stack 的核心

Elasticsearch 是一个开源的分布式 RESTful 搜索和分析引擎、可扩展的数据存储和向量数据库，能够解决不断涌现出的各种用例。作为 Elastic Stack 的核心，Elasticsearch 会集中存储您的数据，让您飞快完成搜索，微调相关性，进行强大的分析，并轻松缩放规模。

产品概述

Elasticsearch 是一个分布式的 RESTful 搜索和分析引擎，可用来集中存储您的数据，以便您对形形色色、规模不一的数据进行搜索、索引和分析。

  • 查询和分析

    从数据中探寻各种问题的答案

    • 定义您自己的搜索方式

      通过 Elasticsearch，您能够执行和合并多种类型的搜索（结构化数据、非结构化数据、地理位置、指标，以及从管道查询语言搜索）。先从一个简单的问题出发，试试看能够从中发现些什么。

    • 大规模存储和分析

      找到与查询最匹配的 10 个文档并不困难 (sysin)。但是如果面对的是十亿行日志，又该如何解读呢？Elasticsearch 聚合让您能够从大处着眼，探索数据的趋势和模式。

  • 速度

    Elasticsearch 很快。快到不可思议

    • 快速获得结果

      如果您能够立即获得答案，您与数据的关系就会发生变化。这样您就有条件进行迭代并涵盖更大的范围。

    • 强大的设计

      但是要达到这样的速度并非易事。我们通过有限状态机实现了用于全文检索的倒排索引，实现了用于存储数值数据和位置数据的 BKD 树，以及用于分析的列存储。

    • 无所不包

      而且由于每个数据都被编入了索引，因此您再也不用因为某些数据没有索引而烦心。您可以用快到令人发指的速度使用和访问您的所有数据。

  • 可扩展性

    可以在笔记本电脑上运行。也可以在承载了 PB 级数据的成百上千台服务器上运行

    原型环境和生产环境可无缝切换；无论 Elasticsearch 是在一个节点上运行 (sysin)，还是在一个包含 300 个节点的集群上运行，您都能够以相同的方式与 Elasticsearch 进行通信。

    它能够水平扩展，每秒钟可处理海量事件，同时能够自动管理索引和查询在集群中的分布方式，以实现极其流畅的操作。

  • 弹性

    我们在您高飞的时候保驾护航

    硬件故障。网络分割。Elasticsearch 为您检测这些故障并确保您的集群（和数据）的安全性和可用性。通过跨集群复制功能，辅助集群可以作为热备份随时投入使用。Elasticsearch 运行在一个分布式的环境中，从设计之初就考虑到了这一点，能够让您永久高枕无忧。

  • 灵活性

    存储和探索数据以满足自身需求

    数据是不断变化的，这使得存储和搜索全部数据变得非常昂贵。Elasticsearch 能让您在性能和成本之间取得平衡。您可以将数据存储在本地以实现快速查询，也可以将无限量的数据远程存储于低成本的 S3 上。借助运行时字段，您还可以快速加载数据并针对变化做出相应调整。

核心优势

Elasticsearch 何以称霸搜索、分析和 AI 三大领域？

这是因为 Elasticsearch 是一个……

  • 数据存储

    全数据类型存储。全内容形式搜索。结构化、非结构化和向量数据通过高效的列式存储统一管理。对我们而言，数据本无差别。

  • 矢量数据库

    语义与语法相遇。文本、图像和多模态向量——全部在一个 API 中。数十亿个嵌入，可部署到您需要的任何地方。

  • 分析引擎

    快人一步。智胜一筹。实时数据分析能够高速运行，即使面对高基数数据也能快速完成聚合及转换。

  • 搜索引擎

    精准度令人惊叹。全文检索、筛选查询、向量搜索和评分机制一应俱全。专为开发人员打造的大规模实时精准搜索系统，深受数据工作者青睐。

  • 地理空间引擎

    实现数据空间可视化。通过地理距离查询、多边形及六边形空间分析功能，对数据进行搜索、整理及展示。

  • 推理服务

    在数据所在的位置，直接运行 Jina AI 的高性能模型和前沿 LLM，无需管理基础架构。通过统一的控制平面，编排搜索、RAG 和智能体工作流。

新增功能

Elastic 9.6：AlertZero、ES|QL S3 数据联邦、通用告警及更多新功能！

2026 年 11 月 23 日

今天，Elastic 宣布 Elastic 9.6 的相关功能现已在 Serverless 环境中推出。预计 Elastic 9.6 将于 12 月初面向 ECH 和自管理部署（Self-Managed）开放。本次版本更新涵盖了 Elastic 平台、在 搜索与 AI、Elastic 可观测性 和 Elastic 安全 方面的重大进展。

Elastic 9.6 有哪些新功能？

Elastic 9.6 引入了一系列全新和扩展的功能，旨在解决每个团队都会面临的常见挑战：海量数据、过多告警，以及用于理解和分析这些信息的时间越来越少。本次版本将 AI Agent 置于核心位置，推出了 AlertZero 和 Elastic nightshift AI SRE，在保持透明度和选择权的同时，为告警响应带来自动化能力。此外，ES|QL 数据联邦让团队能够更加轻松地查询 Elastic 之外的数据。

以下是我们最期待的部分 9.6 新功能概览。

Elastic 平台

Elastic Security

Elastic Security 9.6 在利用 AI Agent 支持安全运营中心（SOC）方面带来了重大增强，并将透明度和选择权放在首位。作为 Elastic Security 智能体层的 AlertZero 现已推出技术预览版，同时还改进了实体分析和终端防护功能。

  • AlertZero，Elastic Security 的智能体层（技术预览版）：大多数团队都根据人员规模来分配告警处理能力，因此，告警队列决定了哪些告警能够得到关注，而其余告警则随着时间推移而逐渐积压，最终未经检查便被搁置。AlertZero 帮助 SOC 团队朝着告警收件箱清零的目标迈进。四个名为 Watches 的 Agent（分类、威胁搜寻、检测和取证）全天候处理告警，关联分散的信号，并提供有证据支持的结论，供团队审核。每个 SOC 的组织方式都不尽相同，因此，您可以自行选择运行哪些 Watches，以及赋予每个 Watch 多大程度的自主执行能力。您可以查看其推理过程，并自由选择所使用的模型，无论您的数据存储在哪里。
  • 通过重点标记实体分析结果，为威胁搜寻抢占先机：过去，实体分析只能提供风险评分，却无法告诉您应该重点关注哪些实体。在 9.6 中，Elastic Security 会突出显示当前需要关注的实体，并说明原因。六种关注信号能够识别状态正在发生变化的实体，包括新近成为高风险的实体和机器学习异常实体。现在，系统还可以跨数据源解析实体，因此，Okta 中的 maria.chen 和 AD 中的 CORP\mchen 将被识别为同一个实体。
  • Linux 勒索软件防护：我们进一步扩展了功能一致性，使 Elastic Defend 在 Windows 和 macOS 上已经提供的勒索软件防护能力也覆盖 Linux 主机。因此，Linux 主机能够获得相同的基于行为的加密防护，无论您以前是否见过该恶意软件。此功能将于 12 月初随 9.6 版本正式推出。

Elastic 平台、搜索与 AI

Elasticsearch 9.6 为用户提供了更多方式，帮助他们更快速、更顺畅地从更多数据中获取答案。主要功能包括：通过 ES|QL 数据联邦直接访问和查询 Amazon S3 数据；借助列式模式（Columnar Mode）实现更快速、成本更低的分析；在 Kibana 中通过 AI Agent 实现团队协作；利用 Jina 驱动的 OCR 技术摄取文档；以及为企业级部署提供更完善的治理和合规能力。

  • 使用 ES|QL 在数据所在位置直接查询，从 Amazon S3 开始：借助 ES|QL 数据联邦（技术预览版），Elasticsearch 现在可以直接查询和搜索存储在不同位置的数据，首先支持 Amazon S3。您可以使用与查询索引数据相同的 ES|QL 语法和 Kibana 工作流，查询 Parquet、CSV、TSV 和 NDJSON 文件，而无需摄取数据、重新建立索引，也无需在不同工具之间协调查询结果。
  • 列式存储与高性能分析：我们将继续完善 Elasticsearch 列式模式（Columnar Mode）（技术预览版），为海量数据提供领先的存储效率、性能和简洁性。
  • Kibana Chat：借助 Kibana 中的多用户聊天等新功能，团队成员可以共享对话，并与同事一起查看和交互 AI Agent 的响应。此外，通过自定义面板，用户只需输入文本提示词，即可轻松创建符合自身需求的可视化组件和图表，无需具备深厚的前端编程或设计经验。
  • Elastic Inference Service：非流式聊天补全功能使 Kibana Chat 能够在不允许 HTTP 流式传输的代理环境后运行，这类环境在受监管行业中十分常见。Elastic Agent Builder 中的可选提示词缓存功能能够降低多轮工作流的成本和延迟。全新的 document_extraction 推理任务类型（现为技术预览版）使用 jina-ocr-v1 模型，自动摄取和处理 PDF 及其他文档格式中的内容，并将其转换为干净的 Markdown 文本。这使这些内容能够供 AI Agent、记录系统和文档归档系统使用。此功能将于 12 月初随 9.6 版本正式推出。
  • 在不同环境中管理身份、支出和审计：当自动化任务、支出和审计记录都有明确的归属时，管理起来就会更加轻松。Elastic Service Accounts 允许您使用专用账户而非个人登录账号或长期有效的 API 密钥来运行定时 Workflows，因此，即使创建者更换团队，自动化任务也能继续正常运行。按日、周、月、季度或年度设置的预算告警，可以在支出达到指定阈值时通知您；Serverless 日志交付功能则可以将审计日志发送到具有独立保留策略的目标位置。在 GovCloud 中，Elastic Cloud 审计跟踪可以帮助您了解是谁修改了部署或组织设置。对于受监管的环境，Elastic Agent 现在支持 FIPS 140-3，Managed Integrations 也已在 GovCloud 中提供。

Elastic Observability

Elastic Observability 9.6 通过提供更多上下文信息来改进应用程序调查，并让开发人员和 SRE 能够将更多产品环境纳入 Elastic Observability。主要更新包括全新的 Elastic nightshift AI SRE（私有预览版）、更丰富的 APM 调查能力、新集成，以及一项名为 Universal Alerting 的全新平台功能。

  • 认识 Elastic nightshift AI SRE（私有预览版）：AI SRE 能够检测和调查整个技术栈中的问题，从每次事故中学习，发现告警未能识别的问题，并提供有证据支持、值得信赖的答案。
  • 结合上下文调查应用程序：在 APM 服务页面中使用带有上下文信息的服务地图，并直接从地图启动一键式 AI 调查。在 Discover 中，可以从 APM 服务进一步深入查看单个 Span。GenAI 跟踪（技术预览版）能够显示提示词、响应和 Token 使用情况，基于 OpenTelemetry 构建，无需使用专有 SDK。
  • 接入团队构建所依赖的工具：使用全新的 Vercel、Supabase 和 Temporal 集成，无需部署 Agent；此外，Elastic Agent 还为受监管环境提供了 FIPS 140-3 支持。
  • 使用 ES|QL 编写任意告警：Universal Alerting 现已正式发布（GA），每条告警都会作为可搜索的数据进行存储。它可以与 Classic Alerting 并行运行，因此无需进行任何迁移。
  • 扩展 Synthetics 监控能力：Synthetics 私有位置现在支持自动扩展。Elastic 会将监控任务分配到 Fleet 策略中的各个 Agent 上；如果某个 Agent 离线，系统会将任务迁移到健康的 Agent 上，因此无需手动进行分片。

了解这些功能及其他新功能的更多信息，请参阅官方文档。
