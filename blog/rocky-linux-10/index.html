以社区方式驱动的企业 Linux

Rocky Linux 是一个开源的企业级操作系统，旨在与 Red Hat Enterprise Linux® 100% 完全兼容。Rocky Linux 正在由社区积极开发中。

以社区驱动为导向，为您带来企业级、生产就绪的 Linux 系统。

Rocky Linux 10.3 现已发布

2026 年 11 月 16 日

Rocky Linux 10.3 搭载内核版本 6.12.0-264.16.1，支持 x86-64-v3、aarch64、riscv64、ppc64le（POWER10 及更高版本）和 s390x（IBM z15 及更高版本）。

Rocky Linux 10 要求 64 位 AMD 和 Intel 系统具备 x86-64-v3 微架构级别，因此不支持 x86-64-v2 及更早版本的硬件。

主要亮点

🐧 编译器和开发工具

  • GCC Toolset 16，作为 Application Stream 提供 GCC 16.2 和 Binutils 2.46，并与系统编译器并存。新增了多项 C++26 特性，包括反射（Reflection）和契约（Contracts），并将默认 C++ 标准更改为 -std=gnu++20
  • LLVM Toolset 22.1.8，将工具集从 LLVM 21 发布系列更新至此版本
  • rust 1.97，引入了上游 Rust 1.93 至 1.97 的变更，并切换到 v0 符号名称修饰格式，以便更准确地反修饰泛型类型
  • golang 1.27.3，新增泛型方法、encoding/json/v2 包，以及实现后量子 ML-DSA 签名的 crypto/mldsa 包
  • gdb 17.2，支持调试 x86-64 CET 影子栈和 AArch64 受保护控制栈（Guarded Control Stacks）
  • Grafana 12.4.3，基于使用 Scenes 库重新设计的仪表板架构构建，并改进了统一告警（Unified Alerting），例如为频繁抖动的告警新增 Recovering（恢复中）状态
  • PCP 7.1.5，为 pmlogcheck 添加自动归档修复功能，新增 Linux 延迟记账和 Device Mapper Multipath 指标，并改进了对损坏归档的处理
  • Grafana PCP 插件 6.1.0，支持 Grafana 12，并提供用于 NVIDIA GPU 指标和 vLLM 推理服务器性能的预构建仪表板

🐧 安全性

  • Keylime 7.14.3 和 keylime-agent-rust 0.2.10，新增由代理驱动的推送式证明功能，适用于边缘和 NAT 环境，同时支持对 AMD SEV-SNP 机密虚拟机进行证据验证
  • fapolicyd 2.0.1，引入多线程并行决策处理、事务性策略和信任数据库更新、动态数据库大小调整，以及 systemd 看门狗集成
  • libreswan 5.4，在 IKEv2 中新增 ML-KEM-768 和 ML-KEM-1024 后量子密钥交换支持，并支持根据 RFC 9370 执行多次密钥交换
  • rust-sequoia-sqv 1.5.0，基于最终版 OpenPGP RFC 9980 提供完整的后量子密码学支持
  • audit 4.2.1，支持使用后量子密码学和 PSK 身份验证的 TLS 1.3 进行远程日志记录，并在 auditctl 中支持 cgroup 和 cgroup2 文件系统过滤
  • FIPS 模式下的 SSH 现在支持并优先使用 mlkem768nistp256-sha256 和 mlkem1024nistp384-sha384 混合后量子密钥交换算法
  • crypto-policies 新增 NO-HMAC-SHA1 子策略，用于在 HMAC 操作中禁用 SHA-1，有助于满足合规性扫描工具的要求
  • OpenSC 0.27.1，新增 PKCS #11 3.2 版本支持和后量子密码学功能
  • aide 提供预配置的 aide-check.timer systemd 单元，用于自动执行完整性检查，并支持在 /etc/aide.d/ 中使用 drop-in 配置
  • libcap-ng 0.9.3，提供新的 cap-audit 工具，用于检查应用程序的能力需求，并为 netcap 增加高级攻击面选项

🐧 内核

  • eBPF 子系统和 perf 已重新基于上游 6.19 版本
  • 启用了运行时验证监视器，包括 sched 和 rtapp 监视器
  • rtla 新增自定义 eBPF 阈值溢出操作，并改进了 EFI 调用路径中 timerlat 堆栈分析的清晰度
  • **完整性度量架构（IMA）**加强了对之前未经评估的文件系统的验证
  • tboot 已更新，以支持可信执行技术（Trusted Execution Technology）工作流程
  • 通过重新基于新版本的 intel-cmt-cat 扩展了对 Intel 资源调配技术（Resource Director Technology）的支持，同时更新了相关的 QAT 和 IAA 用户空间组件
  • IBM Z 工具和密码学软件包已更新，包括 libzpc 版本 2
  • 持续改进 Grace 和特殊用途内存配置的内存管理及 CXL 支持
  • 用于神经网络处理单元（NPU）的 AMD amdxdna 驱动程序现已作为技术预览版提供

🐧 安装程序和镜像创建

  • image-builder CLI 正式发布，可直接通过终端构建操作系统制品和镜像模式资源
  • Image Builder Web 控制台可以从本地主机存储中的任何有效基础镜像创建兼容 bootc 的镜像，包括 Fedora、CentOS Stream 和自定义容器镜像
  • Web 控制台和 CLI 中的镜像类型名称已实现标准化，例如使用 aws 表示 AMI，使用 guest-image 表示 QCOW2
  • Blueprint 现在支持首次启动脚本，并且 Kickstart 可以在安装过程中添加锚定证书，从而支持通过 HTTPS 下载安装镜像，以及在 %pre 和 %post 脚本中使用 HTTPS 下载

🐧 身份管理和基础设施

  • ansible-freeipa 中的 ipauser 和 ipagroup 模块支持新的 query 状态，可以读取用户和组的信息，而不会对其进行修改
  • 可以使用 pam_gssapi_indicators_apply 将 Active Directory AMA SID 映射到身份验证指标
  • access.conf 现在接受数字形式的 UID 和 GID，绕过名称解析，从而加快访问检查速度
  • Valkey 现已支持 RDMA
  • GNOME Kiosk 新增辅助功能，包括辅助功能面板、屏幕放大镜，以及禁用动画的选项

重要变更

以下变更可能会影响现有工作流程。请在升级之前进行检查。

  • 不再支持 WEP。有线等效保密（Wired Equivalent Privacy）标准已被移除，包括从 wpa_supplicant 软件包中移除。升级之前，请删除所有配置为使用 WEP 的网络，并迁移到 WPA2 或 WPA3。
  • ZBUD 压缩页面分配器已被移除。内核内存管理核心已更新至上游 6.15 版本，ZSMALLOC 现在是压缩交换空间默认使用的 zpool 分配器。
  • Grafana 移除了旧版告警功能和 AngularJS 插件支持。如果您依赖其中任何一项，请在升级之前检查您的仪表板。

Rocky Linux 10.3 软件仓库中的部分 Application Streams 将不再获得后续更新。这种情况几乎会在每次发行时发生，因此请检查您所依赖的软件是否正在运行最新的受支持版本。

已知问题

  • xxhash64 被标记为未经 FIPS 批准。在 FIPS 模式下，使用 xxhash64 通过 dmsetup 或 integritysetup 创建的存储卷将无法访问。这两条命令均不会默认使用该算法，因此除非用户明确选择，否则存储卷通常不会受到影响。
  • 在启动选项中使用加密 DNS 和自定义 CA 时，主机名解析会失败。请在 Kickstart 文件中定义安装源，而不要通过内核命令行中的 inst.repo= 或 inst.stage2= 参数进行定义。

Rocky Linux 10 发布公告

2025 年 6 月 11 日

作者：Neil Hanlon（基础架构负责人）、Alexia Stein（社区负责人）

我们很高兴地宣布，Rocky Linux 10 现已正式发布。更新的安装介质、容器、云映像和 Live 映像现已可通过 Rocky Linux 下载页面 获取。请查阅 Rocky Linux 文档中的 发行说明 以获取重要信息，包括已知问题和版本中的详细变更。

重要提示

🐧 支持的微架构级别

Rocky Linux 10 最显著的变化是移除了对 x86-64-v2 架构的支持。现在要求使用 AMD 和 Intel 的 x86-64-v3 64 位架构。

Rocky Linux 10 支持以下处理器架构：

  • 64-bit AMD/Intel x86-64-v3 (x86_64)
  • 64-bit RISC-V (riscv64)
  • 64-bit ARMv8.0-A (aarch64)
  • IBM POWER, little endian (ppc64le)
  • IBM z (s390x)

所有 32 位软件包已从 Rocky Linux 10 中移除。这意味着 32 位应用程序将无法在此版本上运行。请改用带有 32 位依赖项的 64 位库或容器。

🐧 安装程序

  • 默认情况下，用户将拥有管理员权限，除非取消选中该选项。
  • 远程图形访问默认采用 RDP 协议，取代了之前的 VNC。

🐧 DHCP 客户端和服务器

  • RL 10 中的 DHCP 客户端作为 NetworkManager 的内部子系统实现。传统的 dhcp-client 软件包不再被上游支持 (sysin)，已被移除。
  • ISC DHCP 服务器已在上游进入生命周期终止阶段，被其继任者 Kea DHCP 取代。

🐧 桌面环境

  • 在 RL 10 中，Wayland 取代了 X.Org Server。Xwayland 将为尚未迁移到 Wayland 的大多数 X11 客户端提供支持。
  • 部分桌面应用程序和组件也在 RL 10 中进行了替换。

🐧 已知问题

在已安装 passt 的主机上，启用 SELinux 会导致接口启动失败
在使用工作站、服务器或虚拟主机并安装 passt 后端的情况下，如果启用 SELinux，接口将无法启动。详细信息请参见 上游问题报告。

🐧 发布工程更新

Rocky Linux 10 带来一个重要变化：构建系统不再使用 Peridot，而改为使用 Koji。

原因如下：

  • Peridot Two 尚未准备就绪（我们对此表示理解）。我们从早期 Rocky Linux 经验中认识到，在重大版本中使用尚未完成的系统存在风险与低效。这次我们选择更稳妥的方式构建。Peridot Two 将是 Koji 的 XML-RPC 接口在 gRPC 后端上的现代化重构，一旦完成，将对 Koji 用户开箱即用。
  • IMA 签名为优先事项。我们致力支持 Red Hat 引入的 IMA（完整性度量架构），它能通过内核级文件签名验证系统完整性。Rocky Linux 9 的内核已内置此机制。但 Keykeeper（Peridot 的签名工具）目前不支持。因此，我们选择 Koji 来实现精确控制与集成。
  • 兼容性与未来过渡准备。现在用 Koji 构建 Rocky 10，有助于未来平滑过渡到 Peridot Two。届时可无缝导入 Koji 实例中的构建与元数据。

这一决策体现了我们对长期可维护性、社区透明度及安全生产级基础设施的承诺。

Rocky Linux 项目是什么?

Rocky Linux 是一个社区化的企业级操作系统。其设计为的是与美国顶级企业 Linux 发行版实现 100％ Bug 级兼容，而原因是后者的下游合作伙伴转移了发展方向 (sysin)。目前社区正在集中力量发展有关设施。Rocky Linux 由 CentOS 项目的创始人 Gregory Kurtzer 领导。它正处于社区的密集开发中。

稳定可靠 · 企业级 Linux 系统

稳如磐石，无懈可击。

Rocky Linux 直接从 RHEL® 重新构建源代码，因此不管是什么用途，您都可以拥有超级稳定的体验。

  • 生产就绪

    Rocky Linux 是企业级的，通过定期更新和长达 10 年的生命周期支持提供稳定的稳定性，所有的这些都是免费的。

  • 社区强大支持

    社区、赞助商和合作伙伴已做出长期的投入承诺，确保该项目留在社区中。

  • 轻松迁移

    Rocky Linux 免费提供易于使用的迁移脚本，使您可以毫不费力地从其他 Enterprise Linux 发行版迁移。

常见问题解答

“下游合作伙伴转移了发展方向”是什么意思？

CentOS 项目最近宣布了 CentOS 的战略转变，CentOS 以前是作为上游供应商的下游构建版本存在的（即它会在上游供应商之后收到补丁和更新），而现在它将转移为一个上游构建版本（即它会在上游供应商纳入之前测试补丁和更新）。另外，对 CentOS Linux 8 的支持也已从 2029年 5 月 31 日缩短至 2021 年 12 月 31 日。

那么 Rocky Linux 从何而来呢？

Rocky Linux 的目标是像 CentOS 以前那样作为一个下游构建版本，在被上游供应商纳入包更新之后（而不是之前）构建发行。

如果 Rocky Linux 只是 RHEL 的重制版，那么发布候选版本需要这么长时间？

如果我们对 Rocky Linux 的唯一目标是去品牌化和重新打包 RHEL，我们会更快完成。然而，我们必须做的不同的是弄清楚如何将 Rocky Linux 留在社区手中。精心设计此策略可确保 Rocky Linux 永远不会遇到 CentOS 的相同命运。目标不仅是创建一个基于 RPM 的社区管理的 Linux 发行版 (sysin)，而且要确保它可以免费使用并始终处于社区的控制之下，就像 Linux 本身一样。要做到这一点，需要的不仅仅是构建基础设施； 它要求我们建立支持社区的基础结构，确保 Rocky Linux 永远包容、免费和开放。该基础设施由许多合作者和赞助组织围绕可组合性和安全合规性从头开始构建，不仅为基础操作系统提供了基础，还为参与该项目的具有不同利益的整个社区提供了基础。

CentOS 是红帽公司（Red Hat, Inc.）的注册商标，Rocky Linux 项目既不隶属于红帽公司（Red Hat, Inc.），也无受其认可。
